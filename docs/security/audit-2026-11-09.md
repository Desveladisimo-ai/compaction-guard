# Pre-release security audit, 2026-11-09

Done before the first public release (0.1.1). Nothing described here was ever released in a vulnerable state; this page is the record of what was found and how each finding was closed.

## Who reviewed what
| Review | By | Method |
|---|---|---|
| Maintainer audit | The maintainer, with an AI assistant | Read every script; inspected file modes on a real install; reproduced each issue |
| Independent review | A separate AI agent with no access to the author's notes or conclusions | Read-only review of the scripts, hooks, monitor, skills and tests; each finding reproduced in a scratch folder with no network |
| Secret scan | gitleaks (container pinned by digest) | Every commit in the history |
| Static analysis | ShellCheck (`-s sh`) | All scripts |
| Behaviour | The real Claude Code client | Handoff pickup with a benign and a risky handoff; permissions of what it creates |

**Not done:** a human third-party audit or a penetration test. AI reviewers can miss things. The maintainer reproduced each finding below before fixing it, and each fix has a regression test.

## Findings
Severity is the reviewer's judgement of impact on a user, assuming the plugin runs as the user.

| ID | Severity | Finding | Fix | Regression tests |
|---|---|---|---|---|
| SA-01 | Medium | State and handoff files were world-readable (`drwxr-xr-x`, `-rw-r--r--`) because of the default umask | `umask 077`; older installs tightened once | "state folder/files/handoff folder is private to the user", "older install: folder/file tightened" |
| SA-02 | Low | The session id was used raw in file names | Reduced to safe characters | "session id stays inside the state folder", "session id is sanitized into one file name" |
| IR-01 | Medium | A handoff, which the assistant writes after possibly reading untrusted content, was injected with "carry on without waiting", so a planted instruction could survive `/clear` | Handoff is delimited data that grants no permission; risky steps need a question; the announcement names the next step; the wrap-up skill may not copy outside instructions. [ADR 0008](../adr/0008-handoff-is-data-not-instructions.md) | "the handoff is delimited as data", "the notes grant no permission", "risky next steps need a question first", "the announcement names the next step"; real-client refusal of a destructive step |
| IR-02 | Low | An environment value reached shell arithmetic: `COMPACTION_GUARD_STEP_TOKENS='a[$(cmd)]'` ran `cmd` under bash-as-`sh` | Every numeric setting validated with a fallback | "a setting cannot run a command", "step setting cannot run a command", "STEP_TOKENS=0 falls back to the default", "a number with a leading zero is read as decimal" |
| IR-03 | Low | Division by zero and bad numbers made the hooks exit with status 2, which blocks: a window file containing `0` and `COMPACTION_GUARD_CEILING_PCT=x` blocked compaction above the ceiling on dash; the same error in the prompt hook would erase the user's message | Validation plus fail-open: hooks end in success on any unexpected error. [ADR 0007](../adr/0007-fail-open.md) | "a zero window file is ignored: above the ceiling it allows", "a bad ceiling falls back to 95 and allows above it", "prompt hook ends in success with a hostile setting" |
| IR-04 | Low | Reads had no type or size check: a pipe named `pending.md` hung the session start; a symlink had its target injected into the context; a folder in place of the monitor marker made the monitor print a line every second | Only plain files are read; the handoff is capped at 50 KB; the monitor ignores non-files | "a pipe named pending.md does not hang the session start", "a link named pending.md is not followed", "a folder in place of the marker does not make the monitor loop", "an oversized handoff is cut" |
| IR-05 | Low | The record of a block was split without disabling wildcards, and the notice printed the time where the percentage belongs | `set -f`; correct field | "a block record does not expand wildcards", "tells the assistant a block happened, with the percentage" |
| IR-06 | Low | `COMPACTION_GUARD_HOME='/tmp/x$(id)y'` produced shell text the assistant would run | A home path with shell characters is replaced by the default; the command is single-quoted | "a home path with a dollar sign is replaced by the default" |
| IR-07 | Low | The permission tightening followed a symlink or someone else's folder; the log and the archive were unbounded | Tightened only for a real folder owned by the user; log capped at 200 KB; archive pruned at 90 days | "a symlinked home is not tightened", "the log is cut when it grows past 200 KB", "an old archived handoff is removed" |

Of the 21 regression tests added for these findings, 19 fail against the scripts as they were before the fixes; all pass now on macOS, Ubuntu 24.04 and Alpine 3.20.

## Checked, nothing found
- Building the `osascript` and `notify-send` messages: they contain only a number computed by the script.
- Path traversal through JSON values.
- Network calls and data leaving the machine: none; now enforced by a test.
- The skills: `status-line` asks first and cannot be invoked by the model; no unsafe instruction found.
- Secrets and private data in the history: gitleaks found none.

## Not verified
- Whether Claude Code truncates oversized hook output (moot while the handoff is capped).
- Whether two concurrent sessions in the same project can take each other's announce marker. Judged harmless at the time; the 2026-11-10 review showed it is not ([audit](audit-2026-11-10.md)).

## Accepted risk
Hooks and monitors run as the user, as they do for every Claude Code plugin; the plugin cannot reduce that. Prompt injection into the assistant cannot be fully prevented by a plugin; this one bounds the path it controls (ADR 0008).
